Dotfile links, package updates, and vulnerability checks. A small tool for tending to your workstation.

01

What needs doing?

察

Check shell and config locations

conficius dotfiles audit --xdg

Read-only. Use --os-native for OS-native conventions, or --strict to fail on warnings.

Inspect configured links

conficius dotfiles link

Requires a config. Shows what would change; does not create links.

conficius packages pms
conficius packages outdated
conficius packages outdated --pm npm --project ./my-app
conficius packages update
conficius packages update --apply

Where vulnerability data comes from

Installed package names and versions come from package managers and project dependency files. Conficius checks them against two online sources:

  • OSV (Open Source Vulnerabilities). Matches package identity and exact version. npm maps directly; mise and Homebrew packages need explicit identity mappings.
  • ENISA’s European Vulnerability Database (EUVD). Uses product/vendor identities, with mapping overrides in your config.
conficius packages vulnerabilities --pm npm --project ./my-app

Missing mappings mean incomplete coverage, not a clean result. Checks need network access. Findings do not change exit status; inventory or query failures do. Inspection commands accept --json.

03

A file of paths. No guessing.

理

Run conficius init in your dotfiles repository. It creates conficius.toml without overwriting an existing file. Optional examples start commented out; replace them with your paths.

version = 2

[profiles.default]
mode = "denylist"
manager_order = ["mise", "brew", "npm"]

[[tools.zsh.links]]
source = "zsh/.zshrc"
target = "$HOME/.zshrc"
platforms = ["darwin", "linux"]

[[tools.nvim.links]]
source = "nvim"
target = "${XDG_CONFIG_HOME}/nvim"

Sources can be files or whole folders inside the config directory. Relative sources resolve from that directory. Target environment variables expand on load; standard HOME and XDG variables have defaults.

conficius dotfiles link
conficius dotfiles link --apply

A linked folder is the original folder. Tooling that writes sessions, history, or caches through the link writes into your dotfiles repository. Put unwanted generated paths in .gitignore. That keeps them out of Git, not off disk. Link individual config files if runtime data must stay elsewhere.

Example: Zsh runtime files

For a linked zsh/ folder, add these to the repository’s .gitignore. Adjust for your actual layout and history path.

/zsh/.zsh_sessions/
/zsh/.zsh_history
/zsh/.zsh_history.*
/zsh/.zcompdump*
/zsh/*.zwc
/zsh/*.zwc.old

Already-tracked files must be untracked separately.

Config discovery and overwrite rules

Use --config FILE to pick a config explicitly. Otherwise, Conficius searches the current directory and parents, then $XDG_CONFIG_HOME/conficius/conficius.toml, defaulting to ~/.config/conficius/conficius.toml.

Existing real files and directories are never overwritten. --force can replace only symlinks whose destination remains inside the current config repository. Links are validated before changes; failed batches are rolled back.

04

Put a binary on PATH.

備

CLI and TUI are separate binaries. Either runs without the other.

  1. Open GitHub releases. Releases currently ship as prereleases.
  2. Choose conficius_VERSION_OS_ARCH.tar.gz or conficius-tui_VERSION_OS_ARCH.tar.gz. OS: darwin or linux. CPU: arm64 or amd64.
  3. Verify against the release’s checksums.txt, extract, and put the binary on your PATH.

Package operations need the corresponding package manager installed. Online checks need network access.

Or build from source

Go 1.26.8 or newer. From the repository root:

git clone https://github.com/jccguimaraes/conficius.git
cd conficius
go build -o ./bin/conficius ./cmd/cli
go build -o ./bin/conficius-tui ./cmd/tui

Something broken? File an issue.
